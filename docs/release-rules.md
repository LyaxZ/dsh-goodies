# 发布规矩（本插件，来自长期踩坑）

## 1. CHANGELOG 只和上一个已发布版本比

每条都是「读者从上个版本升上来会看到什么不同」。内部调整、做错重做、调试过程一律不写。

- 首版（`[0.1.0]`）只有 `### 新增`，**没有 `### 修复`**——首版没有「修复」可言。
- 之后每次发版：修掉的缺陷进 `### 修复`，行为变了进 `### 变更`。
- 小标题写现象的中性描述，正文 1–2 句只写读者看得见的结果；不写 CSS 属性、函数名、帧数、调试过程。

## 2. 没有明确同意，不发布新版本

`npm publish`、打 tag、创建 GitHub Release 都是不可逆动作。必须逐次得到明确同意才做；「继续」「可以」不构成授权。

已经发布出去的内容里，**npm 包内的文本改不了**（tarball 不可变），只有仓库文件和 GitHub Release 正文可改。所以文案要在发布前定稿。

## 3. 兼容性只写验证过的版本

`engines.dsh`、`dsh.compatibility.dshReleases` 与 README 的对照表只列实际跑过的宿主版本，不列「大概也能用」的预发布版。

## 4. 产物逐字节一致

`build.mjs` 输出统一 LF，仓库 `.gitattributes` 钉 `eol=lf`；发布后核对本地 `npm pack`、Release 资产、npm registry 三份 tarball 的 sha256 是否相同。
